# 내전 워크플로우 명세

- **프로젝트**: Civil War — 오버워치 디스코드 채널별 내전 운영 웹앱
- **버전**: v1
- **연관 문서**: `requirements.md` (§9 워크플로우 요약), `../../구성 초안.md`
- **범위**: 관리자가 로그인한 후 한 번의 내전 세션을 진행·기록하는 전 과정

---

## 0. 용어 정의

| 용어 | 정의 |
|---|---|
| **세션** | 한 자리에서 연속으로 진행되는 내전 (보통 매주 금요일 저녁 1회, N판) |
| **매치(판)** | 한 판의 게임. DB `matches` 1 레코드 |
| **참가자** | 이번 세션에 선발된 정확히 10명 |
| **팀장** | 드래프트 모드에서 팀원을 픽하는 2명 |
| **개인 점수** | 배정 포지션 티어 × 선호도 가중치 (requirements §7.3) |
| **팀 점수** | 5인 개인 점수 합 + 조합 보너스 − 조합 패널티 (§7.4) |

---

## 1. 전제 조건

- 관리자 계정이 발급되어 있고, 본인 소유 채널이 존재 (`channels.owner_admin_id`)
- 해당 채널에 멤버가 **최소 10명 이상** 등록되어 있고, 각 멤버는 역할별 티어·선호 포지션·선호 영웅·선호 맵이 입력되어 있음
- 티어가 하나도 없는 포지션은 **배정 불가** 처리됨 (§7.2)

---

## 2. 전체 플로우

```text
[1] 관리자 로그인
        ↓
[2] 채널 진입 → "내전 시작"
        ↓
[3] 참가자 10명 선택
        ↓
[4] 팀 빌딩 모드 선택
        ├─ 기본(자동 밸런스)
        └─ 팀장 모드(최고티어 / 탱커 / 예능 / 직접 지정)
        ↓
[5] 팀 빌딩 실행
        ├─ 기본: 밸런스 후보 10개 중 랜덤 선택
        └─ 팀장: 팀장 2명 확정 → [6] 드래프트
        ↓
[6] (팀장 모드만) 스네이크 드래프트 — 실시간 점수 표시
        ↓
[7] 팀 확정 (A/B 구성·배정 포지션·팀 점수)
        ↓
[8] 맵 자동 선정 (참가자 선호 맵 합집합에서 랜덤)
        ↓
[9] 영웅 밴 (팀당 1명)
        ↓
[10] 내전 진행 (오프라인 게임)
        ↓
[11] 결과 입력 (승팀·스코어·사용 영웅·메모)
        ↓
[12] 다음 판? ──┬─ 같은 팀으로 한 판 더 → [8]
               ├─ 맵만 바꾸기      → [8]
               ├─ 처음부터 재편성  → [3]
               └─ 세션 종료        → 끝
```

## 3. 단계별 상세

### [1] 관리자 로그인

| 항목 | 내용 |
|---|---|
| 입력 | **아이디(username) + 비밀번호** |
| 처리 | 서버가 `username → 내부 이메일` 변환 후 Supabase `signInWithPassword` → 세션 쿠키 발급 |
| 출력 | 본인 소유 채널 대시보드로 이동 |
| 예외 | 인증 실패 → 에러 메시지. 소유 채널 없음 → 슈퍼관리자 문의 안내 |

### [2] 채널 대시보드 (메뉴 허브)

로그인 후 본인 소유 채널의 대시보드로 진입. 메뉴에서 작업을 선택한다.

| 메뉴 | 기능 | 이동 |
|---|---|---|
| **내전 시작** | 이번 세션 시작 → 참가자 선택 | → [3] |
| **멤버 관리** | 채널 멤버 등록·수정·삭제, 티어·포지션·선호 입력 (F3·F4) | 멤버 관리 화면 |
| **전적·통계** | 채널 내전 기록, 개인 전적 조회 (F12) | 통계 화면 |
| **채널 정보** | 채널명·관리자 정보 확인 (수정은 v1.1) | 정보 화면 |

> "내전 시작"을 누르면 새 세션 컨텍스트 생성 (DB 기록은 첫 매치 저장 시점 [7]에 발생).
> 대시보드 상단에 최근 세션 요약(최근 진행일·판 수)을 표시하면 좋음.

### [3] 참가자 10명 선택

| 항목 | 내용 |
|---|---|
| 입력 | 채널 멤버 목록에서 체크 |
| 처리 | 정확히 10명 선택 강제 (10명 아니면 다음 단계 비활성) |
| 출력 | 선택된 10명 + 각자 역할별 티어·선호 요약 |
| 예외 | 10명 미만/초과 → 다음 단계 진행 불가 |
| UX | 멤버 카드에 주 포지션·대표 티어 배지 표시, 검색·정렬 지원 |

### [4] 팀 빌딩 모드 선택

| 모드 | 설명 |
|---|---|
| **기본 (자동 밸런스)** | 시스템이 균형 잡힌 두 팀을 자동 생성 |
| **팀장 — 최고티어** | 점수 상위 2명을 팀장으로 자동 지정 |
| **팀장 — 탱커** | 탱커 가능자 중 상위 2명을 팀장으로 자동 지정 |
| **팀장 — 예능** | 점수 하위 2명을 팀장으로 자동 지정 |
| **팀장 — 직접 지정** | 관리자가 팀장 2명을 수동 선택 |

### [5] 팀 빌딩 실행

#### 5-A. 기본 모드 — 자동 밸런스

1. 10명을 5+5로 나누는 모든 조합 생성 (역할 슬롯 1탱-2딜-2힐 제약 적용)
2. 각 조합의 팀 점수 계산 (§7.4, 조합 보너스/패널티 포함)
3. 두 팀 `final_score` 차이 절댓값으로 오름차순 정렬
4. 차이가 가장 작은 **상위 10개 조합** 중 무작위 1개 선택
5. → [7] 팀 확정으로 이동

> 공정성 보정(§8.3, 최근 같은 팀 이력 패널티)은 후보 점수에 반영 (v1 가중치는 추후 튜닝)

#### 5-B. 팀장 모드 — 팀장 확정

1. 선택된 모드 기준으로 팀장 2명 결정 (직접 지정 시 관리자 선택)
2. 팀장을 각각 A팀/B팀 첫 멤버로 배치
3. **각 팀장이 자기 배정 포지션을 먼저 지정** (W1 확정) — 탱/딜/힐 중 선택, 티어 있는 포지션만. 이 시점에 팀장의 `individual_score`가 계산됨
4. → [6] 드래프트로 이동 (남은 8명 픽)

### [6] 스네이크 드래프트 (팀장 모드 전용)

| 항목 | 내용 |
|---|---|
| 픽 순서 | **1-2-2-2-1** (팀장 2명 제외, 남은 8명을 8픽 — 아래 상세) |
| 픽 행위 | 현재 차례 팀장이 남은 참가자 1명을 선택 + **배정 포지션 지정** |
| 실시간 점수 | 픽마다 양 팀 `total/bonus/penalty/final` 즉시 재계산·표시 |
| 시각 강조 | 점수 증가 초록, 감소 빨강 잠깐 하이라이트 |

#### 픽 순서 상세 (팀장 2명 이미 배치된 상태, 남은 8명)

```text
순서:  1팀장 → 2팀장 → 2팀장 → 1팀장 → 1팀장 → 2팀장 → 2팀장 → 1팀장
픽번호:  1       2       3       4       5       6       7       8
```

> 팀장이 이미 각 팀 1명(포지션 지정 완료)이므로 8명을 스네이크로 분배해 5:5 완성.
> 배정 포지션은 선호와 달라도 가능 (티어 있는 포지션만, §7.2). 티어 없는 포지션 지정 시 경고.
> 남은 슬롯은 팀장이 차지한 포지션을 뺀 나머지(예: 팀장이 탱 → 남은 슬롯 딜 2·힐 2).

#### 드래프트 UX (드래그앤드롭)

- 중앙 "대기 풀"에 남은 참가자 카드
- 좌/우에 A팀/B팀 슬롯 (탱 1 / 딜 2 / 힐 2)
- 현재 차례 팀의 슬롯만 활성화(하이라이트)
- 카드를 슬롯에 드롭 → 포지션 자동 지정(슬롯 위치 기준), 드롭 후 점수 갱신
- 잘못 놓으면 되돌리기(Undo) 가능 — 단, 픽 순서는 유지
- 티어 없는 포지션 슬롯에는 드롭 불가(빨간 표시)

### [7] 팀 확정

| 항목 | 내용 |
|---|---|
| 표시 | A팀/B팀 구성, 각자 배정 포지션·개인 점수, 팀 총점/보너스/패널티/최종점수 |
| 처리 | 확정 시 `matches`(레코드 생성) + `teams`(A/B) + `team_members`(10건) DB 저장 |
| **공유** | **"디스코드 복사" 버튼** — 팀/포지션/맵/밴을 텍스트로 클립보드 복사 (F12b). 관리자는 이를 디스코드에 붙여넣거나 화면 공유로 참가자에게 전달 |
| 출력 | 맵 선정 화면 |
| 예외 | 점수 차가 과도하면 경고만 표시(강제 차단 X) — 관리자 재량 |

> 복사 텍스트 예시 (맵·밴은 [8][9] 이후 갱신):
>
> ```text
> 🔵 A팀 (23,450)          🔴 B팀 (23,120)
> 🛡️ 홍길동 (라인하르트)    🛡️ 김홍도 (윈스턴)
> ⚔️ 이순신 / 장보고         ⚔️ 장영실 / 세종
> 💉 유관순 / 안중근         💉 이이 / 이황
> 🗺️ 왕의 길   🚫 트레이서 / 겐지
> ```

### [8] 맵 자동 선정

| 항목 | 내용 |
|---|---|
| 입력 | (자동) |
| 처리 | 참가자 10명의 `member_map_preferences` **합집합**에서 무작위 1개 선택 |
| 출력 | 선택된 맵 + 그 맵을 선호한 참가자 목록 표시 (구성 초안 예시) |
| 저장 | `matches.map_code` |
| 예외 | 아무도 선호 맵이 없으면 전체 맵 풀에서 랜덤 |

```text
선택 맵: 왕의 길
선호 멤버: 홍길동, 김홍도
```

### [9] 영웅 밴 (팀당 1명)

| 항목 | 내용 |
|---|---|
| 입력 | A팀 밴 1명 → B팀 밴 1명 |
| 처리 | 영웅 카탈로그(HEROES 상수)에서 선택 |
| 저장 | `matches.banned_hero_a`, `matches.banned_hero_b` |
| 예외 | 밴 생략 가능(NULL 허용) |

### [10] 내전 진행

- 오프라인(실제 게임). 시스템은 대기.
- 화면에는 최종 내전 정보 표시: A/B 구성·배정 포지션·팀 점수·선택 맵·밴 목록 (requirements §9 [14])

### [11] 결과 입력

requirements §9.4 매핑 그대로:

| 입력 | 저장 위치 |
|---|---|
| 승팀 (A/B) | `matches.winner_side` |
| A/B 스코어 | `matches.score_a`, `score_b` |
| 10명 사용 영웅 (**선택 입력**) | `team_members.hero_used` × 10 (nullable) |
| 메모 | `matches.memo` |
| (자동) 팀 승패 | `teams.is_winner` × 2 |

- **필수**: 승팀·스코어. **선택**: 영웅·메모. 영웅 미입력 시 통계에서 "미기록" 처리
- 영웅 입력은 **이름 타이핑 자동완성**: 한글 일부만 쳐도 HEROES 매칭(예: "라인" → 라인하르트). 키보드만으로 빠르게 10명 기입
- 저장은 **단일 트랜잭션**

### [12] 다음 판 분기 (Q5 확정)

결과 저장 완료 후 4개 선택지 제시:

| 선택 | 동작 | 이동 |
|---|---|---|
| **같은 팀으로 한 판 더** | 현재 A/B 팀·배정 포지션 **그대로 복사**해 새 `matches` 생성. 맵 재추첨 + 밴 다시 | → [8] |
| **맵만 바꾸기** | 팀 고정, 새 맵 선정 + 밴 (사실상 위와 동일 흐름, 명시적 표현) | → [8] |
| **처음부터 재편성** | 참가자 선택부터 다시 (멤버 교체·인원 변경 가능) | → [3] |
| **세션 종료** | 워크플로우 종료, 채널 대시보드로 | 끝 |

> "같은 팀으로 한 판 더"와 "맵만 바꾸기"는 내부 동작이 거의 같음(팀 유지 + 새 맵/밴). 버튼을 분리하는 이유는 관리자 의도를 명확히 하기 위함 — UI 라벨만 다르고 동일 핸들러 재사용.

### [13] 매치 수정·삭제 (전적 화면, F12c)

내전 진행 흐름과 별개로, 전적·통계 화면에서 과거 매치를 관리한다.

| 동작 | 내용 |
|---|---|
| **수정** | 결과 오기입 복구 — 승팀·스코어·사용 영웅·메모를 다시 입력해 `matches`/`team_members` UPDATE. 팀 구성 자체는 불변(점수 재계산 안 함) |
| **삭제** | 매치 1건 삭제 → `teams`/`team_members` CASCADE 제거. **본인 소유 채널 매치만** |
| 가드 | 삭제는 확인 다이얼로그. 통계가 즉시 반영됨 |

## 4. 엣지 케이스 / 예외 처리

| 상황 | 처리 |
|---|---|
| 자동 밸런스에서 역할 슬롯을 못 채움 (예: 탱커 가능자 1명뿐) | 가능한 조합이 없으면 경고 + 팀장 직접 지정 모드 권유 |
| 드래프트 중 모든 남은 포지션에 티어 없는 멤버만 남음 | 해당 멤버는 "배정 불가"였어야 하므로 [3] 단계에서 필터. 그래도 발생 시 경고 후 0.75 가중치 강제 적용 옵션 |
| 결과 입력 중 이탈/새로고침 | 매치는 [7]에서 이미 저장됨. 결과 필드만 NULL 상태 → "결과 미입력 매치"로 표시, 나중에 입력 가능 |
| 같은 세션에서 멤버가 중도 빠짐 | "처음부터 재편성"으로 9명+교체 1명 재선택 |
| 무승부 | `winner_side` NULL 허용, `is_winner` 양 팀 false |

## 5. 화면 인벤토리 (이 워크플로우가 요구하는 UI)

| 화면 | 단계 | 핵심 컴포넌트 |
|---|---|---|
| 채널 대시보드 | [2] | 메뉴 허브: 내전 시작 / 멤버 관리 / 전적·통계 / 채널 정보 + 최근 세션 요약 |
| 멤버 관리 | [2] | 멤버 CRUD, 티어·포지션·선호 영웅·선호 맵 입력 |
| 전적·통계 | [2] | 매치 이력, 개인 전적(사용 영웅·멤버·승패) |
