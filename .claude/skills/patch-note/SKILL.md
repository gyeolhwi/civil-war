# patch-note — 패치노트 복붙 블록 생성 루틴

패치노트 글을 정제해 **웹 게시판(`/app/patch-notes` 작성 폼)에 그대로 붙여넣을 복붙 블록**으로 출력한다.
게시판에 올리면 공개 페이지 `/patch` 와 디스코드 `/패치노트`(최신 1건)에 반영된다.
※ 라이브 글은 DB(`patch_posts`)에 저장되며 **사용자가 폼에 붙여넣어** 올린다. 이 스킬은 **복붙 블록을 출력**하고 **아카이브 사본을 `docs/patch-notes/`에 저장**한다(라이브 DB는 직접 건드리지 않음).

## 모드 판단 (먼저)
**🎮 오버워치 섹션은 두 모드 모두 항상 작성한다. 차이는 출처뿐이다.**
- **(A) 컨텍스트/링크 제공** — 사용자가 나무늘보/제미나이 요약·블리자드 링크 등 패치 내용을 함께 주면: 그 내용 + Blizzard 공식을 정합해 🎮 섹션을 작성한다.
- **(B) 아무것도 안 줌 (스킬만 호출)** — 별도 입력 없이 `/patch-note`만 부르면: **직접 Blizzard 공식 패치노트 최신본을 WebFetch/WebSearch 로 가져와** 🎮 섹션을 작성한다. (더 이상 🎮 섹션을 생략하지 않는다)
  - 공식 패치노트: <https://overwatch.blizzard.com/ko-kr/news/patch-notes/> (최신 글이 맨 위. 특정 날짜는 `#patch-YYYY-MM-DD` 앵커)
- **공통:** 내전 편성 사이트·봇(모이라)에 사용자 체감 변경이 있으면 🛠️ 섹션을 덧붙인다(없으면 생략).

## 단계

1. **오버워치 공식 패치 수집·첨삭 (두 모드 공통, 출처: Blizzard 공식 + 나무늘보, 이 둘만)**
   - **B 모드(입력 없음): 직접 Blizzard 공식 패치노트 최신본을 WebFetch/WebSearch 로 가져와** 그 내용으로 작성한다. (공식: <https://overwatch.blizzard.com/ko-kr/news/patch-notes/>)
   - **A 모드(요약/링크 제공): 준 텍스트와 Blizzard 공식을 정합** — 같은 항목은 합치고, 공식과 어긋나면 공식 우선, 나무늘보에만 있는 유용한 디테일은 살린다.

   **추림 관점 = "스타디움을 안 하는 일반 오버워치 유저" (내전 플레이어 기준 아님). 우선순위 (위에서부터 담고, 분량 넘치면 아래부터 잘라냄):**
   1. ✨ **신규·리워크 영웅** — 있으면 최상단. 1~2줄.
   2. **영웅 업데이트(핵심 — 가장 충실히 적는 섹션)** — **`🛡️ 탱커` `⚔️ 딜러` `💉 힐러` 세 그룹으로만 나눠** 적는다(역할 머릿글에만 이모지). **체감 큰 영웅은 영웅당 한 줄 + 구체 수치**(예: `• 겐지 ↑ 명상 35→50, 튕겨내기 8→6초`). 영웅 줄엔 이모지 없이 방향 `↑`/`↓`만. 각 역할 핵심 영웅을 수치까지 담되(이름만 나열 금지), 사소한 미세조정 영웅은 `A·B·C ↓ 소폭 하향` 식으로 묶는다.
   3. 🔧 **퍼크(Perk) 변경** — **눈에 띄게 바뀐 것만 한두 줄.** (퍼크 = 경기 중 영웅별로 고르는 소형/대형 강화. 큰 변화 없으면 생략)
   4. 🗺️ **신규·변경 맵 + 경쟁전** — 신규 맵, 맵풀/랭크 시스템 변화가 있을 때만.
   5. ⚙️ **핵심 시스템·모드·UI** — 6v6/신규 모드, 매치메이킹, 눈에 보이는 편의기능 등 체감되는 것만.
   6. 🐛 **주요 게임플레이 버그 수정** — 영웅 능력 버그 등 체감되는 것만. 그래픽/사운드/사소한 버그는 제외.
   7. 🎁 **코스메틱** — 신규 배틀패스/콜라보/주요 이벤트만 **딱 한 줄**로 압축.

   **제외(확정):** 🏟️ **스타디움 전용 밸런스·업데이트**(통째로 제외), 인사·잡담·구독요청·광고·말장난, 근거 없는 추측(절대 지어내지 말 것).

   **분량 가드:** **영웅 업데이트는 충실히**(핵심 영웅별 구체 수치), 시스템·맵·이벤트는 **압축**한다. 🎮 섹션 전체 대략 **12~18줄**. 넘치면 영웅 외 항목(7→6→5…)부터 줄인다. 각 줄은 한 줄로 간결히(이모지는 절제 — 아래 출력 규칙 참고).

2. **내전 편성 사이트·봇(모이라) 업데이트 정리** — 현재 사용자가 체감하는 변경을 `🛠️ 내전 편성 사이트 · 봇(모이라) 업데이트` **별도 머릿글 섹션**으로 구획해 적는다.
   - `git log --oneline` 으로 직전 패치 글 이후(또는 최근) 커밋을 본다.
   - 사용자가 체감하는 것만(신규 화면/기능, 추가된 영웅·맵, 눈에 보이는 수정). 내부 리팩터·chore·문서·CI·DB/RLS·마이그레이션은 제외.
   - 직전 패치 글과 겹치면 가장 최근·대표 기능 위주로 추린다. **정말 사용자용 변경이 하나도 없을 때만** 섹션을 생략한다(🎮 오버워치 섹션만 출력).

3. **아카이브 파일 저장** — `docs/patch-notes/<발행일 YYYY-MM-DD>-<영문 slug>.md` 에 새 파일을 만든다(**파일명은 발행일=오늘 기준**. 차곡차곡 누적·복사 원본·git 이력). 포맷:
   ```markdown
   ---
   title: <폼 제목>
   patch_date: <블리자드 공식 패치 날짜 YYYY-MM-DD>
   published: <발행일=오늘 YYYY-MM-DD>
   ---

   <폼 본문 — 아래 복붙 블록과 동일>
   ```
   기존 파일은 덮어쓰지 말고 새 파일로 추가한다.

4. **복붙 블록 출력** — 아래 두 덩어리를 코드펜스로 각각 보여준다. 사용자가 `/app/patch-notes` 폼의 제목/본문에 그대로 붙여넣는다.

   제목(한 줄):
   ```
   <예: 시즌 3 '호랑이 굴 속으로' — 신규 영웅 시온 + 밸런스>
   ```

   본문 (모든 줄 사이에 빈 줄 — 줄바꿈 규칙 참고. **머릿글로 구획을 나눈다**):
   ```
   🎮 오버워치 공식 패치 — <패치명>

   패치일 <YYYY-MM-DD> · 발행일 <YYYY-MM-DD>

   **영웅 업데이트**

   🛡️ 탱커

   • <영웅> ↑ <구체 수치>

   ⚔️ 딜러

   • <영웅> ↓ <구체 수치>

   💉 힐러

   • <영웅> ↑ <구체 수치>

   **시스템 · 경쟁전**

   • <시스템/경쟁전 변경>

   **맵 · 이벤트**

   🗺️ <신규 맵 한 줄>

   🎁 <이벤트·스킨 한 줄>

   ━━━━━━━━━━━━━━━

   🛠️ 내전 편성 사이트 · 봇(모이라) 업데이트

   • <사용자용 변경 1>

   출처: Blizzard 공식 패치노트
   ```

   - 본문 마크다운: `**굵게**`·`[라벨](url)` 사용 가능(웹/디스코드 모두 렌더).
   - **날짜 줄:** 헤더 바로 아래 `패치일 <YYYY-MM-DD> · 발행일 <YYYY-MM-DD>` 한 줄. **패치일**=블리자드 공식 패치 날짜, **발행일**=폼에 올리는 날(오늘). 폼에 날짜 입력 칸이 없으므로(`title`/`body`만) 본문에 적어야 보인다.
   - **이모지 절제(남발 금지):** 블록 머릿글 `🎮`·`🛠️`, 역할 머릿글 `🛡️ 탱커`·`⚔️ 딜러`·`💉 힐러`, 맵·이벤트 줄 `🗺️`(맵)·`🎁`(이벤트)까지만. 그 외 영웅·시스템 줄엔 이모지 없이 `•` + 텍스트(방향 `↑`/`↓`만 허용).
   - **머릿글 구획:** 🎮 안을 `**영웅 업데이트**`(→ `🛡️ 탱커`·`⚔️ 딜러`·`💉 힐러` 하위 그룹) · `**시스템 · 경쟁전**` · `**맵 · 이벤트**` 로 나눈다.
   - **오버워치 ↔ 내전 구분:** 🎮 오버워치 블록과 🛠️ 내전 블록 사이에 **구분선 `━━━━━━━━━━━━━━━`** 를 한 줄 넣어 두 영역을 시각적으로 분리한다(웹·디스코드 어디서나 글자 그대로 보임).
   - **🎮 오버워치 섹션은 항상 출력**한다(B 모드면 직접 가져온 Blizzard 공식 기준). 🛠️ 내전 섹션 머릿글은 `🛠️ 내전 편성 사이트 · 봇(모이라) 업데이트` (현재 사용자 체감 변경만).
   - 출처 줄은 **실제 사용한 곳만** 적는다: B 모드(직접 수집)면 `출처: Blizzard 공식 패치노트`, A 모드에서 나무늘보 요약을 받았으면 `· 나무늘보 패치노트` 를 덧붙인다. 그 외 출처는 표기하지 않는다.

   ### 줄바꿈 규칙 (중요 — 불릿이 한 줄로 붙는 문제 방지)
   - **모든 불릿·섹션 줄 사이에 빈 줄을 한 줄 넣는다.** 즉 항목마다 `내용\n\n내용` 형태.
   - 이유: 불릿 기호 `•` 는 마크다운 **리스트 마커가 아니라** 일반 텍스트라, 단일 줄바꿈으로만 이으면 마크다운 렌더러(CommonMark 계열)가 연속 줄을 **한 문단으로 합쳐** 줄바꿈이 공백이 된다(= 불릿이 한 줄로 붙음). 빈 줄로 분리하면 각 줄이 독립 문단이 되어 **웹 `/patch`(whitespace-pre-wrap)·디스코드 임베드·일반 마크다운 어디서나** 줄바꿈이 보존된다.
   - 불릿 기호는 `•` 유지(빈 줄로 분리하면 안 붙는다). 굳이 `-` 마크다운 리스트를 쓸 필요 없음.

## 주의
- 출처는 **Blizzard 공식 + 나무늘보** 두 곳만. 다른 출처(인벤/게임메카/나무위키)는 사실 확인용으로만 보고 출처 표기엔 넣지 않는다.
- 사실에 근거 없는 내용 금지. 불확실하면 빼거나 사용자에게 묻는다.
- 코드/DB를 직접 건드리지 않는다. 사용자가 웹 폼에 붙여넣어 올린다(배포 불필요, 즉시 반영).
